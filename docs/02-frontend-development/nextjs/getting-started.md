# Getting Started and Project Structure

The Next.js starter creates a React application with the framework's routing,
development server, and build tooling already connected.

## Create and run a project

```bash
npx create-next-app@latest
cd my-app
npm run dev
```

The setup prompts vary by release and selected options. The development
server normally opens at `http://localhost:3000`. To use another port with
the standard npm script, run `npm run dev -- --port 3001`. A command such as
`npx create-next-app@13.4.12` intentionally selects an older release; use it
only when reproducing a project that requires that exact version.

## Common App Router files

| File or folder | Typical role |
|---|---|
| `app/` | App Router routes and shared UI |
| `app/page.tsx` | Page for the root URL `/` |
| `app/layout.tsx` | Shared layout around routes in its segment |
| `app/globals.css` | Global CSS imported by the root layout |
| `app/favicon.ico` | Site icon |
| `public/` | Public static files, referenced from the site root |
| `package.json` | Scripts and dependency declarations |
| `next.config.ts`, `.js`, or `.mjs` | Optional framework configuration |
| `tsconfig.json` | TypeScript compiler and project settings, when using TypeScript |
| `eslint.config.*` | Lint configuration, depending on starter version |
| `next-env.d.ts` | Framework TypeScript declarations, normally generated |

Generated files differ according to Next.js version and starter choices. The
`pages/` directory belongs to the older Pages Router when used for routes;
the App Router uses `app/`.

### A route segment's special files

```text
app/
  layout.tsx       shared UI for this segment and descendants
  template.tsx     remounted shared UI when navigation requires a fresh instance
  page.tsx         route's user-facing page
  loading.tsx      loading fallback for eligible work
  error.tsx        segment error boundary (Client Component)
  not-found.tsx    not-found UI for the segment
  route.ts         HTTP handler; cannot coexist with page.tsx at same segment
```

These files are conventions, not mandatory files for every folder.
`route.ts` handles requests and is not the page rendering file.

## Practical example

```tsx
// app/page.tsx
export default function HomePage() {
  return <main><h1>My learning site</h1></main>;
}
```

This file defines the root route in the App Router.

## Developer perspective and terminology

Run the development server while editing, then run a production build before
deployment. **Development server** provides local iteration; **production
build** creates deployable output; **static asset** is a file served without
being generated by a page component.

## Common misconceptions

- `public/logo.svg` is normally referenced as `/logo.svg`, not
  `/public/logo.svg`.
- A folder does not become a visible route unless it contains the appropriate
  route file.
- `route.ts` is not a synonym for `page.tsx`; it defines an HTTP handler.
- Starter defaults can change; check the files created by your installed
  version.
